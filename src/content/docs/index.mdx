## What this site covers

This docs site is organized around the tools and standards in this workspace:

- `aflock` for AI agent policy enforcement with signed attestations
- `rookery` for modular attestation plugins and custom binary assembly
- `witness` and `go-witness` for attestation creation, signing, and verification
- `in-toto` attestations and ITE proposals for the underlying model
- Sigstore, Chainguard, and SPIFFE/SPIRE for the surrounding trust ecosystem
- Kubernetes-native delivery patterns that connect CI evidence to admission and
  runtime identity
- Local lab tracks that let you practice the model without needing cloud
  infrastructure

## Find things quickly

- Use the search control in the header when you already know the term, command,
  or project name.
- Use the [Glossary](/reference/glossary/) when a term like `DSSE`, `SVID`, or
  `predicate` is the blocker.
- Use [How the tools connect](/reference/how-tools-connect/) when you need to

  overlap or diverge.

  filtered to beginner, intermediate, or advanced depth.

## Suggested path

1. Read [in-toto attestations](/in-toto-attestations/) for the trust model.
2. Go to [aflock](/aflock/) for the highest-priority project.
3. Use the guided [Tutorial tracks](/tutorials/) to move from a local attestation loop to policy-backed CI/CD and delegated verification.
4. Use [Local labs](/local-labs/) when you want a repeatable workspace-rooted sandbox for build, attest, sign, verify, Rego, and manifest checks.
5. Use [witness](/witness/) and [go-witness](/go-witness/) to understand CLI and library execution paths.
6. Read [Reference pipelines](/reference-pipelines/) for copy-paste GitHub Actions and GitLab CI patterns that add policy gates to real release flows.
7. Read [Kubernetes-native SSCS](/kubernetes-sscs/) to see how those primitives become a cluster delivery flow with admission and workload identity.
8. Read [Adoption guides](/adoption-guides/) to see what real rollout patterns look like across companies and CNCF projects.
9. Finish with [Sigstore](/sigstore/), [Chainguard concepts](/chainguard/), and [SPIFFE / SPIRE](/spiffe-spire/) to place the tools in a broader production context.
